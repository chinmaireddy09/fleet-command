# Contributing

Improvements are welcome — corrections, clearer wording, a station layout that worked better in
practice, a hazard this misses.

## Licensing of contributions

**Anything you intentionally submit for inclusion — by pull request, patch, or otherwise — is
licensed under [condition 7 of the Fleet Command License 1.1](LICENSE):** it is licensed to the
author and to all recipients of the Work on the same terms as the rest of it.

**You keep ownership of what you wrote.** Condition 7 grants a licence; it does not transfer
your copyright. If you want different terms for a particular contribution, say so plainly when
you submit it.

## What makes a good change here

These skills are instructions read by both people and machines, so the bar is different from
ordinary code:

- **Plain words.** If a term needs a glossary, it is the wrong term. This project has already
  thrown away one entire invented vocabulary for exactly that reason.
- **Say what actually happened.** The most useful parts came from real failures — a `git add -A`
  that swallowed another session's work, a stash pile nobody could attribute, the same finding
  filed twice. Concrete beats hypothetical.
- **Never write down a guarantee you have not tested.** If you cannot prove a claim on a real
  project, say so in the text rather than asserting it.
- **Keep the standing rules intact** unless you can show they are wrong. Each one exists because
  something broke.

## Practical

Fork, branch, open a pull request describing what changed and why. If it changes behaviour rather
than wording, say how you verified it.
